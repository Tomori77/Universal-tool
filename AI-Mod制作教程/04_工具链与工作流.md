# 04 · 工具链与工作流

> 本页记录反编译、构建、打包、贴图、编码和排错。环境路径与依赖的完整清单查根目录 `工具与依赖.md`。

## 1. 反编译

使用 ilspycmd 查询 Elin.dll 的类和方法：

```powershell
ilspycmd "D:\Steam\steamapps\common\Elin\Elin_Data\Managed\Elin.dll" -t TraitCrafter -r "D:\Steam\steamapps\common\Elin\Elin_Data\Managed" | Out-File TraitCrafter.cs -Encoding utf8
ilspycmd Elin.dll -l c > types.txt
ilspycmd -p -o <输出目录> Elin.dll
```

注意：`-l` 必须带实体类型参数；`-r` 使用程序集目录；输出默认可能不是 UTF-8，保存中文源码时显式指定编码。单类源码归档到 `docs\研究\`，全量反编译归档到 `docs\研究\Elin_full\` 或对应目录。新结论只记录到根目录 `反编译速查.md`。

## 2. 构建与打包

标准流程：

1. 删除旧的 `docs\待转移\<Mod名>\`。
2. `dotnet build -c Release -o docs\待转移\<Mod名>`。
3. 复制 `LangMod\`、`Texture\`、`package.xml` 和 `preview.jpg`。
4. 删除发布目录中的 `*.pdb`。
5. 检查包内没有源码、工程、obj、refs。

预编译 DLL 是插件 Mod 的发布方式；不要把仅用于 Script 编译的源码目录当作 DLL 插件发布。发布包由用户复制到游戏 `Package\`，AI 不直接改游戏目录或启动游戏。

## 3. 贴图

### 图片目录与责任

每个 Mod 的图片工作区建议为：

```text
<Mod目录>\图片\
├── 未修改图片\   # 用户提供原始图片
├── 使用图片\     # 处理后或无需处理的最终图片
└── 归档\         # 已使用的原始图片
```

操作顺序：

1. 用户将原始图片放入 `图片\未修改图片\`。
2. AI 发现新图片后，必须先询问用户是否需要处理；未经确认不得修改。
3. 用户确认需要处理时，使用脚本去背景、裁剪和缩放，并将结果保存到 `图片\使用图片\`。
4. 用户确认不需要处理时，不修改图片，直接复制到 `图片\使用图片\`。
5. 按物品 id 命名，例如 `ut_auto_farming.png`，然后复制到 `Texture\`。
6. 确认已使用后，将原始图片移动到 `图片\归档\`。
7. 发布包只复制 `Texture\`，不复制 `图片\` 下的工作文件夹。

### 处理命令

```powershell
.\tools\适配贴图.ps1 -Src item.jpg -Out item.png -Mode texture
.\tools\适配贴图.ps1 -Src cover.jpg -Out preview.jpg -Mode cover -Size 512
```

物品贴图应为 32×32、透明背景、俯视视角、主体占满；封面为 512×512 JPG。

## 4. 文档工作流

每个 Mod 建议维护三份文档：

- `<Mod名>设计规范.md`：需求、定稿决策、实现步骤、验证方式和待决策项。
- `<Mod名>物品清单.md`：面向玩家的物品用途和获得方式。
- 根目录 `反编译速查.md`：跨 Mod 复用的已验证 API 和机制。

原则：每步可验证；模板可复制；经验性结论明确标记；不要在多个文档重复维护同一份底层结论。

## 5. 编码与离线环境

- Markdown、源码和 JSON 使用 UTF-8。
- PowerShell 脚本尽量只写 ASCII。
- PowerShell 读取 UTF-8 文件时指定 `-Encoding UTF8`。
- xlsx 生成用 xlsxwriter，生成后用 openpyxl 读回检查。
- 网络不可用时优先查看本地 `docs\Elin.Docs-master\`；离线 NuGet 的 `NU1900` 告警在无外部包依赖时通常无害。
- Mod Options DLL 可从本地工坊缓存复制到 `docs\refs\`。

## 6. 日志排错

| 问题 | 位置或关键词 |
|---|---|
| 插件加载、BepInEx 报错 | `BepInEx\LogOutput.log`，搜索 `Loading`、`0 plugins to load` |
| Mod 的 Unity 日志 | `Player.log` |
| 源表导入 | `Player.log` 搜 `#source`、`#mod-content` |
| 配方重建 | `Player.log` 搜 `Rebuilding recipe list`、`Failed to create recipe` |
| 配置内容 | `BepInEx\config\` |

出现问题时，先确认发布包内容和日志，再根据具体 API 查 `反编译速查.md`，不要直接猜测方法名或数据字段。
